# 3단계 예약 실행 구현 기록

## 동작 흐름

1. 팝업의 대기 등록이 완성된 설정을 검증해 단일 실행을 저장합니다.
2. Chrome 알람이 예약 오픈 약 90초 전에 예약 탭을 열고, 탭의 콘텐츠 스크립트가 오픈 시각까지 기다립니다. 오픈 전에 읽은 달력은 오픈 시각에 다시 로드합니다.
3. 사이트의 기존 달력·시간 선택 핸들러를 사용합니다. 설정된 희망 시간을 입력 순서대로 검사해 사용 가능한 첫 시간을 선택하고, 선택 내용을 저장한 다음 NEXT로 이동합니다.
4. 정보 입력 화면에서 지점·테마·날짜·시간 식별자를 다시 확인합니다. 인원, 예약자, 010 전화번호, 무통장입금, 필수 동의를 입력합니다. 선택 마케팅 동의는 켜지 않습니다.
5. CAPTCHA는 사용자가 직접 완료합니다. 확장 프로그램은 응답 유무만 보고 토큰을 저장하거나 기록하지 않습니다.
6. 제출 직전 실행 상태를 submitting으로 기록한 뒤 사이트의 예약하기 버튼을 한 번 클릭합니다. 완료 화면을 같은 예약 탭에서 확인하고 앞 단계 날짜·시간과 일치할 때 완료로 표시합니다.

## 안전한 중단

- 실행 상태와 예약 탭 ID를 저장합니다. 한 번에 하나의 실행만 허용하고, 중지는 이후 단계 진행을 막습니다.
- 예약 정보가 불일치하거나 사이트 구조가 바뀐 경우 자동 진행을 중단합니다.
- 이미 예약하기 클릭을 시도했거나 시도 여부가 불확실하면 자동 재제출하지 않습니다. 약 90초 후에도 완료 화면이 확인되지 않으면 확인 필요 상태로 남깁니다. 이는 예약 실패의 증거가 아니므로 예약 조회 화면을 확인해야 합니다.
- 브라우저 재시작 시 대기 알람을 재등록합니다. 예약 탭이 없어졌을 때도 자동으로 다시 예약하지 않습니다.
- 입금 완료 여부는 완료 화면만으로 판단하지 않습니다.

## 변경 파일

- manifest.json: 예약 사이트 전용 콘텐츠 스크립트와 알람·탭·저장 권한.
- extension/background.js: 사전 탭 준비, 단계 전환, 단일 제출 잠금, 중지와 결과 대기.
- extension/content-script.js, extension/runner.js: 사이트 화면에서 시간 선택과 정보 입력을 수행하는 실행기.
- extension/popup.html, extension/popup.js: 상태·예약 탭 이동·중지 안내.
- src/keyescape-site.js: 필수 입력 확인, CAPTCHA 응답 유무 확인, 최종 버튼 단일 클릭.
- extension/settings.js: 후보 시간 형식을 HH:mm으로 제한.
- test/keyescape-site.test.js, test/run-state.test.js: 중복 클릭과 상태 전이를 검증.

## 검증과 한계

- 로컬 DOM 및 Service Worker 모의 테스트 44개 통과. 모든 JavaScript 모듈 구문 검사 통과.
- 사용자가 제공한 저장 HTML에서 확인한 DOM 계약을 사용했습니다. 외부 사이트 스크립트나 CAPTCHA 서비스를 테스트에서 실행하지 않았습니다.
- 일반 Chrome 확장 프로그램을 실제 사이트에서 설치·실행하여 끝까지 이동하는 검증은 아직 수행하지 않았습니다. 추가 예약을 생성하지 않았습니다.
- Chrome 알람은 예약 시각에 정확히 실행된다고 보장되지 않습니다. 일찍 탭을 열어 대기하지만 브라우저가 종료·절전 상태이거나 사이트가 늦게 응답하면 지연될 수 있습니다.
- reCAPTCHA의 교차 출처 프레임을 확장 프로그램이 직접 클릭하거나 푸는 기능은 구현하지 않았습니다. CAPTCHA를 사용자가 완료하면 다음 단계가 진행됩니다.
