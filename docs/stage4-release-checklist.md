# 4단계 설치·사용 및 출시 점검 기록

## 설치와 갱신

1. Chrome에서 `chrome://extensions`를 엽니다.
2. 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
3. 저장소 루트 폴더를 선택합니다. 이 프로젝트는 번들링 없이 소스 폴더를 직접 로드합니다.
4. 코드를 변경한 뒤에는 확장 프로그램 카드의 새로고침 버튼을 누릅니다. Chrome이 확장 프로그램을 다시 로드했는지 확인합니다.
5. 확장 프로그램 팝업의 상태 대시보드에서 **편집**을 열고 대상·일정·예약자 정보를 입력합니다. 희망 시간은 목록에 추가해 순서를 확인하고, 오픈 시각은 24시간제로 입력합니다. **설정 저장** 후 요약 값을 다시 확인합니다.

이름과 휴대전화는 현재 Chrome 프로필의 `chrome.storage.local`에 저장됩니다. 그 프로필을 함께 사용하는 사람은 저장값에 접근할 수 있습니다. 설정 화면에서 올바른 지점·테마 식별자와 예약 대상 이름을 확인해야 하며, 다른 테마의 ID를 추측해 입력하지 않습니다.

## 예약 실행 전 확인

예약은 되돌릴 수 없는 외부 사이트 작업입니다. 실제 예약을 의도한 실행에서만 대기 등록을 하세요. 자동 실행은 오픈 약 90초 전에 탭을 준비하고 날짜·희망 시간 중 첫 번째 가능 항목을 고른 다음 정보를 입력합니다. Chrome 알람, 절전, 사이트 응답에 따라 지정 시각보다 늦을 수 있습니다.

팝업에서 **저장하고 대기 시작**을 누른 뒤 상단 상태·카운트다운과 진행 현황을 확인하세요. 진행 중 설정은 잠깁니다. CAPTCHA 대기와 결과 확인 필요 상태에서는 **예약 탭 열기**가 우선 표시됩니다. 탭이 닫혔다면 예약 조회에서 직접 결과를 확인하세요.

예약 탭과 팝업에서 다음 항목을 확인합니다.

- 지점, 테마명, 방문 날짜와 화면에 표시된 시간이 설정과 맞습니다.
- 인원, 예약자 이름, 휴대전화, 결제 방법과 예상 금액이 맞습니다.
- 필수 동의 항목이 표시되고 선택 마케팅 동의는 켜져 있지 않습니다.
- CAPTCHA는 사람이 직접 처리해야 한다는 안내가 보입니다.
- 설정과 다른 화면, 정보 불일치, 예상하지 못한 날짜·시간이면 CAPTCHA를 풀지 말고 **중지**를 누릅니다.

이 확장 프로그램은 CAPTCHA 응답이 확인되면 예약하기를 한 번 클릭합니다. 화면만 살펴보는 점검이라면 CAPTCHA를 완료하지 마세요. 테스트 목적으로 임시 예약을 만들지 마세요. Chrome 팝업의 **예약 탭 열기**는 현재 실행 탭으로 돌아가는 용도입니다.

## 완료 또는 결과 불명

완료 상태는 같은 예약 탭에서 완료 화면을 확인했다는 뜻입니다. 예약금 입금 완료를 뜻하지 않습니다. 사이트가 늦게 응답하거나 탭이 닫히면 실행은 **확인 필요**로 멈출 수 있으며, 이 상태만으로 실패나 성공을 단정하지 않습니다. 재실행 전에 키이스케이프 예약 조회에서 기존 예약을 확인하고, 예약이 없다고 확인한 뒤에만 새 실행을 준비하세요. 무통장입금 안내와 기한도 사이트에서 별도로 확인해야 합니다.

## 로컬 검증

Node.js 24 이상에서 프로젝트 폴더에서 실행합니다.

```powershell
npm ci --ignore-scripts
npm test
npm run check
```

저장 HTML은 별도로 정적 검사할 수 있습니다. 파일은 직접 전달한 원본 경로를 사용하며 프로젝트에 복사할 필요가 없습니다.

```powershell
npm run check:snapshots -- "$env:USERPROFILE\Downloads\예약1.html" "$env:USERPROFILE\Downloads\예약2.html" "$env:USERPROFILE\Downloads\예약3.html" "$env:USERPROFILE\Downloads\완료.html"
```

스냅샷 검사는 HTML을 파싱하되 그 안의 JavaScript를 실행하거나 외부 서버에 요청하지 않습니다. 이름, 전화번호, 예약번호의 실제 값이나 CAPTCHA 응답을 출력하지 않습니다. 제출 버튼을 누르지 않는 정적 진단이므로, 라이브 사이트 동작이나 Chrome 확장 로딩을 증명하지 않습니다.

검증 결과: `npm test`는 실행·사이트 검증 44개, 상태 대시보드 1개, 배너 7개, 시작 흐름 4개로 총 56개가 통과했고 `npm run check` 및 `package.json`·`manifest.json` JSON 파싱도 통과했습니다. 저장 HTML 정적 검사에서는 예약1·2가 저장된 테마 선택과 표시된 화면이 맞지 않아 모든 대상에서 `TARGET_MISMATCH`로 중단됐습니다. 예약3은 괴록 정보 입력 화면, 완료.html은 괴록 완료 화면으로 판정됐습니다. 두 화면은 서로 다른 예약 정보여서 연속 이동 검증으로 간주하지 않습니다. 정적 검사는 제출하지 않습니다.

팝업 화면은 `test/popup-browser.html`의 테스트 전용 Chrome API 장면에서 실제 `extension/popup.html`·`popup.css`·`popup.js`를 렌더링해 PC 기본 폭 520×600과 480×600, 560×600으로 확인했습니다. 저장·대기·중지와 시간 입력, CAPTCHA·제출·확인 필요·완료·실패 상태를 점검했습니다. 이 장면은 실제 Chrome 확장 로딩이나 실사이트 예약 페이지 검증을 대신하지 않습니다.

## 확인 현황 및 완료 기준

| 기준 | 상태 | 근거 |
|---|---|---|
| 압축해제 설치와 사용 절차 문서화 | 충족 | 위 설치·갱신 절차와 README |
| 개인정보, CAPTCHA, 중지와 불확실 결과 안내 | 충족 | 위 실행 전·완료 점검 |
| 로컬 테스트와 구문 검사 | 충족 | `npm test` 56개 통과, `npm run check` 통과, JSON 파싱 통과 |
| 제공된 저장 HTML의 정적 검사 | 충족(불일치 검출) | 예약1·2의 대상 불일치와 예약3·완료의 괴록 구조를 확인 |
| 일반 Chrome에서 확장 설치 후 예약 정보 입력 화면까지 실사이트 확인 | 미확인 | 저장 HTML과 모의 DOM은 실제 네트워크 실행을 대신하지 않음 |
| 실사이트 최종 예약 생성 | 미수행 | 검증용 예약은 생성하지 않음 |

실사이트의 최종 제출까지 확인하려면 실제로 원하는 예약을 진행하는 상황에서 확인해야 합니다. 별도 테스트 예약 생성은 이 단계의 검증 방법으로 사용하지 않습니다.

## 2026-09-23 실제 실행 불능 원인 수정

사용자 증상은 예약 탭은 열리지만 오픈 시각 이후 날짜·시간 선택이 시작되지 않는 것이었습니다. 실행기는 최초 `GET_RUN_CONTEXT` 요청에서 아직 알 수 없는 실행 ID를 보내지 않는데, 배경 스크립트가 그 요청에도 실행 ID 일치를 요구해 `RUN_NOT_ACTIVE`로 거절했습니다. 실행기는 응답을 받지 못해 조용히 종료됐습니다.

바인딩된 예약 탭에서 온 최초 정보 요청만 실행 ID 없이 허용하도록 수정했습니다. 이후 상태 전환 요청에는 종전처럼 실행 ID를 요구합니다. 최초 요청이 다른 이유로 실패하면 실행기가 `BOOTSTRAP_FAILED`를 보내 대기 상태를 오류로 전환하도록 했습니다. 회귀 테스트는 실행 ID 없는 최초 요청의 성공, 다른 탭 및 잘못된 실행 ID의 거절을 확인합니다.

저장된 예약1·2 HTML의 `TARGET_MISMATCH`는 당시의 정적 저장본에서 드롭다운 선택 상태와 표시 내용이 맞지 않은 것을 가리킵니다. 이번에 읽은 일반 Chrome 페이지에서는 URL의 괴록 식별자와 화면의 괴록 선택이 일치했습니다. 이 정적 저장본 불일치를 현재 실행 불능의 원인으로 볼 수 없습니다. 실제 예약 화면에서 대상 식별자와 표시 테마가 잠시 어긋나면 최대 8초 동안 갱신을 기다립니다. 끝내 일치하지 않으면 중단하는 보호는 유지합니다.

Chrome URL 확인 실패는 이전 Windows UI 도구의 안전 검사에서 발생했습니다. 별도 브라우저 연결로 키이스케이프 URL과 초기 달력은 확인했지만, 이어진 화면 캡처에서 사이트가 개발자 도구 차단 화면으로 전환됐습니다. 이 연결을 통한 날짜·시간 선택 및 정보 입력 화면 확인은 계속할 수 없었습니다. 사이트 차단을 우회하거나 실제 예약을 생성하지 않았습니다.

수정 후에는 `chrome://extensions`에서 이 확장 프로그램을 새로고침하고, 이전 실행 상태를 중지한 다음 새 대기 실행을 등록해야 새 Service Worker 코드가 적용됩니다. CAPTCHA를 풀지 않는 사전 점검에서는 자동 제출이 일어나지 않습니다.
