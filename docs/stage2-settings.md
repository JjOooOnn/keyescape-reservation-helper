# 2단계 설정 및 실행 상태

## 범위

예약 프로필과 일정 입력, 브라우저 로컬 저장, 한 번에 하나의 대기 상태, 명시적인 중지를 구현했습니다. Chrome Service Worker가 대기 상태를 저장하고 팝업이 이를 표시합니다.

## 설정 항목

- 대상: 지점 ID, 테마 ID, 테마 정보 ID, 테마명. 기본 테마는 AYAKO이며 ID는 확인된 값으로 미리 채웁니다. 다른 대상은 사용자가 확인한 값을 입력할 수 있습니다.
- 일정: 방문 날짜, 순서가 우선순위인 희망 시간 최대 8개, 예약 오픈 날짜와 시각. 오픈 시각 기본값은 11:00:00.
- 예약자: 인원 2~4명, 이름, 010 휴대전화.
- 예약 시각, 날짜(방문일은 오늘 이후), ID, 전화번호를 검사합니다. 대기 등록 시 모든 항목을 다시 확인하고 오픈 시각이 미래인지 검증합니다.

설정은 chrome.storage.local의 keyescapeSettings에 저장됩니다. 이름과 휴대전화가 포함된 실행 스냅샷은 keyescapeRun에 저장됩니다. 두 값 모두 Chrome 프로필의 로컬 저장소에 두며 chrome.storage.sync는 사용하지 않습니다. 확장 프로그램 저장소는 TRUSTED_CONTEXTS로 제한합니다. 대기 중에는 입력과 설정 저장을 잠그며 START_RUN 메시지는 Service Worker에서 순서대로 처리해 중복 대기를 거부합니다. STOP_RUN은 상태를 stopped로 기록합니다.

## 현재 상태와 경계

“예약 대기 등록”은 설정을 검증하고 대기 상태를 저장합니다. 2단계에서 타이머, 알람, 예약 페이지 열기, 날짜·시간 선택, 예약자 자동 입력, CAPTCHA 처리, 예약하기 제출은 수행하지 않습니다. 팝업은 아직 실행 단계가 연결되지 않았음을 표시합니다. 중지 버튼은 미연결 대기 상태를 취소합니다. 3단계에서 예약 실행기를 연결해야 이 상태가 실제 일정 예약으로 이어집니다.

입금 완료 여부는 이 단계에서 다루지 않습니다. 설정 화면과 저장은 실제 사이트에 요청하지 않습니다.

## 변경 파일

- manifest.json: storage 권한과 module Service Worker 등록.
- extension/settings.js: 설정 기본값·정규화·검증.
- extension/background.js: 중복 방지 대기 상태와 중지 처리.
- extension/popup.html, extension/popup.css, extension/popup.js: 설정·저장·대기/중지 UI; 1단계 진단 유지.
- package.json: 추가된 모듈 구문 검사 명령.
- README.md: 설치 후 갱신과 설정 설명.

## 검증

- node --check로 모든 프로젝트 모듈 구문 검사.
- JSON.parse로 manifest와 package JSON 파싱.
- 단위·Chrome 실사용 테스트는 실행하지 않았습니다. 실행 테스트는 별도 사용자 요청 없이 수행하지 않는 현재 지침을 따릅니다. 확장 프로그램 reload 및 폼 저장 확인은 아직 필요합니다.
