# 키이스케이프 예약 도우미 — 4단계

예약 오픈 시각에 키이스케이프 예약 페이지에서 날짜·시간을 선택하고 예약 정보를 입력하는 Chrome 확장 프로그램입니다. CAPTCHA는 사용자가 직접 완료해야 합니다. 완료되면 예약하기 버튼을 한 번 누르고 완료 화면을 확인합니다.

실제 목표 테마는 AYAKO이며, 제공된 괴록 HTML로 공통 입력 흐름을 검증했습니다. 모듈은 지점·테마 식별자와 이름을 인자로 받아 같은 화면 구조를 사용하는 다른 테마에도 적용할 수 있습니다. 모든 지점·테마의 호환성을 확인했다는 뜻은 아닙니다.

## 다른 PC에서 내려받기

GitHub 저장소 페이지의 **Code** 메뉴에서 HTTPS 주소를 복사한 뒤, 터미널에서 저장소를 복제합니다. 아래 예시의 `OWNER`와 `REPOSITORY`를 GitHub 계정/조직명과 저장소명으로 바꿉니다.

    git clone https://github.com/OWNER/REPOSITORY.git
    cd REPOSITORY

Chrome 확장 프로그램 실행에는 Node.js나 npm 설치가 필요하지 않습니다. 프로젝트에 빌드 단계가 없으므로 복제한 저장소 폴더를 Chrome에서 바로 로드합니다.

## 크롬 설치 및 사용

1. 크롬 주소창에 chrome://extensions 를 입력합니다.
2. 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
3. 복제한 저장소의 루트 폴더를 선택합니다. `manifest.json`이 있는 폴더입니다.
4. 코드 변경 후에는 chrome://extensions에서 확장 프로그램의 새로고침 버튼을 누릅니다.
5. 확장 프로그램 **키이스케이프 예약 도우미**를 열고 상태 대시보드의 **편집**에서 예약 대상·방문 날짜·희망 시간·오픈 날짜와 시각·예약자 정보를 입력합니다. 희망 시간은 **시간 추가**로 목록에 넣고 순서를 조정합니다. 시각은 24시간제로 입력합니다.
6. **설정 저장** 후 요약을 확인하고 **저장하고 대기 시작**을 누릅니다. 오픈 시각 약 90초 전에 예약 탭을 준비합니다.
7. 예약 탭에서 CAPTCHA를 직접 완료합니다. 완료 뒤 예약하기 버튼은 확장 프로그램이 한 번 누릅니다.
8. 팝업 상단의 상태·카운트다운, 예약 요약, 진행 현황을 확인합니다. CAPTCHA 대기나 결과 확인 필요 상태에서는 **예약 탭 열기**로 직접 확인하고, 필요하면 **중지**를 누릅니다.

예약 대상 ID와 테마명은 설정 화면에서 직접 지정합니다. 개인정보와 설정은 chrome.storage.local에 저장되며 동기화되지 않습니다. 대기 등록 중에는 설정 변경이 잠깁니다. 1단계 진단 목록에는 첨부 HTML에서 확인한 AYAKO·괴록·투투 어드벤쳐가 표시됩니다.

완료·실패·중지 후 **새 예약 설정**은 다음 실행의 입력 화면을 엽니다. 저장하면 **예약 준비** 홈으로 돌아오며, 새 설정 요약과 대기·선택·CAPTCHA·결과 단계가 표시됩니다. 홈의 **저장하고 대기 시작**으로 실행합니다. 마지막 실행 기록은 변경하지 않고 접힌 **이전 실행**에 분리합니다. 결과 확인 필요 상태에서는 편집·재시작할 수 없고 자동 재제출하지 않으며, 제출을 시도한 이력이 있으면 새 실행 전에 예약 조회에서 결과를 확인해야 합니다.

이 확장 프로그램은 debugger 권한을 사용하지 않습니다.

## 로컬 검사 (선택)

기능 검증을 실행하려면 Node.js 24 이상을 설치하고 복제한 저장소 폴더에서 실행합니다. 이는 Chrome 확장 프로그램을 사용하는 데 필수는 아닙니다.

    npm ci --ignore-scripts
    npm test
    npm run check

원본 저장 HTML을 로컬에서 추가 진단하려면:

    npm run check:snapshots -- "$env:USERPROFILE\Downloads\예약1.html" "$env:USERPROFILE\Downloads\예약2.html" "$env:USERPROFILE\Downloads\예약3.html" "$env:USERPROFILE\Downloads\완료.html"

HTML 검사에서는 원본 스크립트를 실행하거나 외부 리소스를 불러오지 않습니다. 요약 결과에 예약자 이름, 연락처, 예약번호 실제 값, 접근용 URL 쿼리, CAPTCHA 응답은 포함하지 않습니다. 원본 HTML과 부속 파일은 프로젝트에 복사하지 않았습니다.

별도 번들링/빌드는 필요 없습니다. jsdom은 로컬 DOM 검증용 개발 의존성이며 크롬 확장 프로그램 실행에는 사용되지 않습니다.

## 사이트 모듈

src/keyescape-site.js의 createKeyescapeSite(document, { target })를 사용합니다.

target은 { branchId, themeId, themeInfoId, name } 형식입니다. 식별자는 select#zizum, select#theme의 value 및 option의 data-themenum으로 확인해야 합니다. 식별자나 테마명을 추측해서 전달하지 않습니다.

- inspect(): 현재 단계·상품·날짜/시간 목록 또는 인원/금액 구조를 읽습니다. 호환되지 않으면 { ok: false, code, message }를 반환합니다.
- inspectCompletion({ date, time }): 완료 본문·상품·예약 정보 목록을 검사하고 앞 단계 날짜·시간과 비교합니다. 완료 화면에 없는 지점/테마 ID 및 입금 여부는 확인하지 않습니다. 실행기는 저장한 제출 시도와 같은 탭의 이동 이력을 함께 확인합니다.
- selectDate('YYYY-MM-DD'): 열린 달력의 사용 가능한 날짜를 클릭합니다. 시간표 로딩 완료는 호출자가 기다려야 합니다.
- selectTime('HH:mm'): 이 모듈로 선택한 날짜의 시간을 클릭하고 사이트가 갱신한 요약을 검증합니다.
- openDetails(): 검증된 선택에 한해 사이트의 NEXT를 한 번 클릭합니다. 실제 페이지 전환 완료는 호출자가 확인해야 합니다.
- backToCalendar() / changeMonth(-1 또는 1): 사이트의 기존 달력 버튼을 클릭합니다.
- inspectDetails({ date, time, slotId }): 앞 단계에서 고른 날짜·시간·시간 식별자가 정보 입력 화면과 일치하는지 확인합니다.

동작 메서드는 문제가 있으면 CompatibilityError를 던집니다. 같은 페이지에서 같은 모듈 인스턴스를 유지해야 날짜·시간 검증이 연결됩니다. 페이지 전환 후에는 새 인스턴스를 만들고 앞 단계의 선택 결과를 inspectDetails()에 전달합니다.

예약 실행기는 저장된 선택값을 정보 입력 화면에서 다시 확인하고 이름·전화번호·인원·무통장입금 및 필수 동의를 입력합니다. 선택 마케팅 동의는 체크하지 않습니다. CAPTCHA 응답은 읽어서 완료 여부만 확인하고 토큰은 저장하거나 출력하지 않습니다. 제출 시도는 저장소에 먼저 기록하고, 불확실한 결과를 자동 재제출하지 않습니다. 완료 화면은 같은 예약 탭에서 실제 제출 시도 이후 열린 경우에만 성공 상태로 처리합니다. 입금 여부는 별도로 확인해야 합니다.

## 2단계 설정

- 예약 대상 지점 ID·테마 ID·테마 정보 ID와 테마명은 직접 입력합니다. 기본값은 사용자 목표인 AYAKO입니다.
- 방문 날짜와 최대 8개의 희망 시간(입력 순서가 우선순위), 예약 오픈 날짜·시각(기본 11:00:00), 인원 2~4명, 예약자 이름과 010 휴대전화를 설정합니다.
- 설정 저장은 입력값을 보관합니다. 대기 등록 시 필수값, 날짜·시간 형식, 전화번호, 미래 오픈 시각을 다시 검사합니다.
- 실행이 대기 중이면 설정을 잠급니다. 같은 시각에 중복 등록하지 않으며, 중지 버튼은 대기 상태를 취소 표시합니다.
- 이름과 전화번호가 포함된 설정 및 실행 스냅샷은 이 Chrome 프로필의 로컬 저장소에만 기록됩니다. 브라우저 프로필을 공유하는 사람에게는 접근 가능할 수 있습니다.
- 예약 대기 상태는 Chrome 알람으로 복원하고, 예약 탭 안에서 오픈 시각을 기다립니다. 알람·브라우저 절전·사이트 응답 지연 때문에 정확히 지정 시각에 실행된다고 보장할 수는 없습니다.

## 실행 중 상태

- **대기 / 준비 / 선택 중**: 오픈 시각 전 예약 탭 준비와 날짜·시간 선택을 진행합니다.
- **CAPTCHA 대기**: 사용자가 예약 탭에서 CAPTCHA를 완료해야 계속 진행합니다.
- **제출 결과 확인 중**: 예약하기를 한 번 누른 상태입니다. 응답이 늦거나 화면이 닫히면 확인 필요 상태로 멈춥니다.
- **완료**: 같은 탭의 완료 화면에서 테마·날짜·시간을 확인했습니다. 입금 확정 상태는 아닙니다.

실사이트 Chrome에서 확장 프로그램을 설치해 최종 예약까지 검증하지 않았습니다. 실행 전 확인 항목과 확인 한계는 [4단계 설치·사용 및 출시 점검 기록](docs/stage4-release-checklist.md)을 따르세요. 실제 예약을 의도하지 않은 점검에서는 CAPTCHA를 완료하지 마세요. 완료 상태도 예약금 입금을 확인해 주지는 않습니다.

예약 탭만 열리고 진행되지 않던 초기 실행 ID 요청 오류를 수정했습니다. 코드 변경 후 Chrome 확장 프로그램을 새로고침하고, 이전 실행을 중지한 뒤 새로 대기 등록하세요.
